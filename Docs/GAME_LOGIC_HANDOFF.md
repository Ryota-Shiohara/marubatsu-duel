# ARまるばつ対戦 ゲームロジックの受け渡し仕様案

人間のプレイヤー2人が、同じ紙の3×3盤面に○と×を交互に書いて対戦する。○が先手。カメラで読み取った記号をゲーム側が着手として確認し、その結果をARで表示する。

この文書は担当間で合意するための案。型名は既存コードに合わせて調整できる。

## 担当とデータの流れ

| 担当 | 作るもの |
| --- | --- |
| 認識側 | カメラ画像から9マスを読み取り、安定して検出した新しい○・×を着手候補として渡す |
| ゲーム側 | 着手の可否、確定盤面、手番、リーチ、勝敗、リセットを管理する。カメラなしの仮入力で動作確認できる形にする |
| AR表示側 | 確定盤面を受け取り、駒の表示、中央マスの登場演出、勝利・引き分け演出を行う |

認識側 → `MoveCandidate` → ゲーム側 → `BoardSnapshot` → AR表示側

マス番号は印刷した盤面を正面から見て、左上から横順。中央は `4`。

```text
0  1  2
3  4  5
6  7  8
```

## 認識側からゲーム側へ

`MoveCandidate` は以下の2項目を持つ。

| 項目 | 値 |
| --- | --- |
| `CellIndex` | マス番号 `0〜8` |
| `Mark` | `Circle`（○）または `Cross`（×） |

ゲーム側の入口は `TryApplyMove(candidate)` を想定し、着手を受理したかを返す。対局中で、対象が空きマスで、現在の手番と記号が一致する場合に受理する。範囲外のマス、手番違い、埋まったマス、終局後の候補は拒否し、盤面を更新しない。

認識側は `Empty` と `Unknown` を候補に含めない。同時に複数の新しい記号が見つかった場合は、どれが今回の着手か絞れるまで保留する。認識側が同じ候補を再送しても、受理済みのマスはゲーム側で拒否する。

## ゲーム側から表示側へ

`BoardSnapshot` は、ゲーム側で確定した状態をひとまとめにした値。後続の着手で過去のスナップショットが変わらないようにする。

| 項目 | 値 |
| --- | --- |
| `Revision` | 状態の更新番号。初期値は `0`。着手の受理とリセットで増やす |
| `Cells` | マス番号順の9要素。各マスは `Empty / Circle / Cross` |
| `NextTurn` | 次に書くプレイヤーの記号。終局時はなし |
| `LastMove` | 最後に受理した着手のマス番号と記号。初期状態とリセット直後はなし |
| `Threats` | 対局中のリーチ一覧。各項目に記号、揃った2マス、残りの空きマスを含める |
| `Outcome` | `Playing / CircleWon / CrossWon / Draw` |
| `WinningCells` | 勝利ラインの3マス。勝利以外は空 |

リーチは、縦・横・斜めの1ラインに同じ記号が2つあり、残りが空いている状態。○・×の両方を対象にし、同時に成立するラインはすべて返す。終局時の `Threats` は空。最後の着手で複数ラインが揃った場合、表示する1ラインをゲーム側で一貫した順序に従って選ぶ。

リーチは内部の状態として受け渡す。現行の [PROJECT_SPEC.md](../PROJECT_SPEC.md) はリーチ通知や次の一手のヒントを対象外としているため、対戦中にリーチ演出を見せるかは別途合意する。

## 更新のタイミング

- **初期表示**では `GetSnapshot()` で現在の状態を取得し、駒と手番を表示する。
- **着手受理直後**は、盤面、手番、リーチ、勝敗を更新した状態を `OnSnapshotChanged` で1回通知する。拒否した候補では通知しない。
- **リセット直後**は、全マス空欄・○先手・`Playing`・`LastMove` なしの状態を1回通知する。認識側は紙が空になったことを確認して受付を再開する。
- **盤面を見失ったとき**は、認識側が候補の送信を止め、表示側が駒を隠す。ゲーム側の確定盤面は保持し、再認識時に同じ盤面を表示する。

表示側は、新しい着手で `LastMove.CellIndex == 4` なら中央の登場演出を行う。新しい更新で `Outcome` が勝利になったら、`WinningCells` のラインを表示する。同じ更新番号を再取得したときや追跡が復帰したときは、駒の表示を復元し、着手や勝利の演出を重複して再生しない。

## カメラなしでの確認例

| 仮入力 | 期待する結果 |
| --- | --- |
| ○4 | 中央に○、`LastMove = (4, Circle)`、次は× |
| ○4 → ○0 | 2手目は手番違いで拒否。中央の○と×の手番を保持 |
| ○0 → ×4 → ○1 | ○のリーチとして揃ったマス `[0, 1]` と空きマス `2` を返す |
| ○0 → ×4 → ○1 → ×8 → ○2 | `CircleWon`、勝利マス `[0, 1, 2]`、次の手番なし |
| 終局後に着手候補を渡す | 拒否し、勝敗と盤面を保持 |
| リセットする | 全マス空欄、○先手、リーチ・勝利マス・最後の着手をクリア |

`Tools/Test-Recognition.ps1` で認識と対局のカメラなしテストを実行できる。Unityで数字キーを使う仮入力は、`TicTacToeGameManager` の `Enable Keyboard Moves` を有効にしたときに使える。
